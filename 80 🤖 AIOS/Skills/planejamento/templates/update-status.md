# Modelo de update de status

## Índice
1. Como usar
2. Status
3. Modelo
4. Riscos

## 1. Como usar
Para a review da sprint, para a liderança de design ou para o PO. Curto (até umas 200 palavras): a conclusão primeiro, não o caminho. A Julia revisa antes de mandar; o Claude não envia nada.

## 2. Status
- **No prazo:** andando como planejado, sem risco relevante. Use só quando for verdade.
- **Em risco:** mais devagar que o planejado ou um risco apareceu; pode precisar ajustar escopo ou prazo. Sinalizar cedo é bom, não é fracasso.
- **Fora do prazo:** vai perder o compromisso sem ajuda (cortar escopo, mais prazo, mais gente). Use quando precisar de ajuda.

Quando o status mudar, diga por quê.

## 3. Modelo

```markdown
**<Iniciativa ou sprint>** · Status: <No prazo / Em risco / Fora do prazo>

**Em uma frase:** <o mais importante>

**Pronto:**
- <o que ficou pronto e o que isso destrava>

**Em andamento:**
- <o quê> · previsão: <data>

**Riscos:**
- <risco>: <o que estou fazendo>. <O que preciso de alguém, se precisar>.

**Decisões que preciso:**
- <decisão>: <opções e minha recomendação>. Até <data>.

**Próximos marcos:**
- <marco> · <data>
```

## 4. Riscos
Diga o risco com clareza ("existe o risco de X porque Y"), o impacto, o que está sendo feito e o pedido, se houver. Pedido específico: "decisão sobre X até sexta", não "preciso de apoio".
